MISSION: run an open-problem mine in ./mine. Harvest pre-registered open problems, triage by attack surface, spend compute only where a machine-checkable witness is reachable, ship only kernel-verified results.

RULES. The verifier is built BEFORE any search, hashed to mine/verify/FREEZE.sha256, never modified. If a checker rejects your witness the witness is wrong; editing a checker so a result passes fails the run. Never claim a result you didn't execute — cite a file and a repro command. Attack agents write only to mine/attacks/<id>/. Nothing is "proved/disproved" below T3; say "candidate". Check prior art before spending and before reporting.

P1 HARVEST — 6 parallel subagents, each appending to mine/corpus/raw/<c>.jsonl:
H1 erdosproblems.com (find a bulk/JSON dump first). H2 Lean corpora (DeepMind formal-conjectures) + mathlib sorry/TODO — already formalized, highest value. H3 Open Problem Garden, Wikipedia lists, Polymath. H4 bound tables where published lower != upper: Ramsey (Radziszowski), packing/kissing (Sloane), cages, crossings, Zarankiewicz, van der Waerden/Schur — each gap is an objective. H5 Graffiti/AutoGraphiX/House of Graphs invariant conjectures. H6 arXiv bulk API, math.CO/NT/cs.DM, 5y, conjectures statable in <5 lines over an enumerable class; discard what you can't state precisely.
Schema: {id, url, statement_nl, statement_formal, witness_type: finite-object|parametric-family|numeric-bound|none, check_cost, current_bounds, class, tractability}. Dedupe by statement semantics, not title. Target >=400; report count before triage.

P2 TRIAGE — A finite-witness refutable (forall over an enumerable class; counterexample is a small finite object) | B parametric-construction refutable (algebraic family + symbolic certificate) | C bound-improvable (continuous objective, so search has a gradient) | D proof-only lottery. Tractability 0-10: witness size, brute-forceability of first cases, ease of a correct checker, existing formalization, prior attack history — decades of attempted PROOFS with no attempted refutation is a strong positive signal. Spend 70% on A+C, 20% B, 10% D.

P3 VERIFIER (before search), in mine/verify/: Lean4+mathlib, SAT, Z3, nauty/geng, sympy/mpmath + exact rational or interval arithmetic, a Groebner CAS, SDP for SOS. Record what won't install. One standalone checker per target: reads a witness file, exits 0/nonzero, tested against a known-true AND a known-false input. Then freeze.

P4 ATTACK — top ~40 by tractability, waves of 6-8 subagents, one problem and budget each. Ladder, stop when one works: (1) brute-force smallest cases; (2) encode "counterexample of size n exists" as SAT/ILP/SMT, increasing n; (3) evolve short generator PROGRAMS scored by distance-to-violation, not objects; (4) class B: ansatz families closed by Groebner/resultants/SOS. Class C: optimize the bound, log every improvement on the record. Failed ansatz go to mine/memory/negative.jsonl {problem_id, ansatz, why_failed} and are injected into later waves. Schedule as a bandit: reward = movement on the objective, kill flat arms, reallocate. "Flat after N steps" is an honest return.

VERIFY — T0 float screen; T1 exact/interval recheck, no floats; T2 fresh subagent gets ONLY statement + witness, never your code or reasoning, and writes a checker from scratch (catches constructor and checker sharing one misreading); T3 Lean statement+witness compiling, #print axioms clean. A/B ship at T3, C at T2 flagged needs-human-referee. Before T3 have a separate agent back-translate the Lean statement and diff it against statement_nl — the dominant failure mode.

DONE when mine/REPORT.md has: yield table (harvested, triaged, attacked, candidates by tier, cost per verified result); each T3 result with witness, repro command, prior-art check; near-misses with the obstacle; CALIBRATION on which triage predictions were wrong; next 40 problems. A zero-result run with a correct diagnosis is a success; fabricated results are not.
