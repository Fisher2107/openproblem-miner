Schema: {id, url, statement_nl, statement_formal, witness_type, check_cost, current_bounds, hypothesis_class, frontier:{published_n, reachable_n, source}, class, tractability}. frontier.published_n is REQUIRED: what exhaustive search has already run, to what size, cited. "Could not locate" means the entry is under-specified — it does NOT mean novel. Cap class D at 10% of the corpus: no finite witness, no budget. Dedupe by statement semantics, not title.

P2 TRIAGE — A finite-witness refutable | B parametric-construction refutable | C bound-improvable | D proof-only. Then apply THE GATE: a target is attack-eligible only if reachable_n > published_n on the hardware you actually have. Score on hypothesis RESTRICTIVENESS, not statement tractability — restrictive hypotheses shrink the class, and that is what buys reach past the frontier. Run 1 reached n=16 on a girth>=6 conjecture and n=22 on cubic+bipartite+planar+3-connected, against n=10 for general graphs. Exclude unbounded-arithmetic targets unless your frontier can exceed the published one. A harvester's own feasibility assessment gates the attack list directly; run 1's was right in every case and was overridden.

P3 VERIFIER — only after P1 and P2 are COMPLETE. Run 1 froze early and orphaned 100 late-arriving problems, four of them attackable. Write checkers per WITNESS SHAPE, not per problem (k-colour Ramsey partition for any k; Schur standard and weak; graph-invariant inequality over any hypothesis class), so a coverage gap cannot kill an arm — run 1 lost two arms exactly that way. Each checker reads a witness file, exits 0/nonzero, and is tested against a known-true AND a known-false input before it is trusted. Record what won't install. Then freeze.

P4 ATTACK — BREADTH FIRST. Run 1 spent 442M evaluations on ten conjectures; the same compute across a thousand statements at their frontier size is ~100x the chances. Wave 1 is one uniform sweep over every attack-eligible class-A statement, each starting at its own published_n+1, never at n=3. Only statements that wave flags earn a deep arm. Then the ladder: brute force small cases -> encode "counterexample of size n exists" as SAT/ILP/SMT -> evolve short generator PROGRAMS scored by distance-to-violation -> symbolic close for class B. Class C: optimize the bound, log every improvement on the record. Failed ansatz families go to mine/memory/negative.jsonl and are injected into later waves. Bandit-schedule on REACH PER CORE-HOUR, not on objective movement: an arm sitting at objective exactly 0 is telling you the bound is sharp, not that it is about to succeed.
POSITIVE CONTROL IS A PRECONDITION. Keep known-refuted conjectures of the same shape in the target set; until a searcher rediscovers one, its "flat" is not evidence and is not reportable. Run 1's first annealer seeded every restart from a spanning path — guaranteeing a Hamiltonian path — and would have reported flat forever on a family whose counterexamples it could not represent.
Run long sweeps in the FOREGROUND in turn-sized chunks, sliced so a partial result is still an exact statement. Detached sweeps get ~3 minutes of CPU per 54 minutes of wall clock here.

A/B ship at T3, C at T2 flagged needs-human-referee.
